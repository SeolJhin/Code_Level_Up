Q1. forEach, map, filter 차이점
A1.
    공통점 : 배열순회 메서드
    차이점 : 
                forEach : 반환값이 없는 출력 저장용 
                map : 각 배열 요소를 변환해서 새 배열 생성
                filter : 조건을 만족하는 요소만 반환

                const nums = [1, 2, 3, 4, 5];

                // forEach: 반환값 없음, 부수 효과(출력, 저장 등)용
                nums.forEach(n => console.log(n));
                // 1 2 3 4 5 출력, 반환값은 undefined

                // map: 각 요소를 변환해서 새 배열 생성
                const doubled = nums.map(n => n * 2);
                // [2, 4, 6, 8, 10]

                // filter: 조건을 만족하는 요소만 남김
                const evens = nums.filter(n => n % 2 === 0);
                // [2, 4]

        // 직접 구현시 Que, Loop, Thread
        BlockingQueue<Runnable> queue = new LinkedBlockingQueue<>();

        Thread loop = new Thread(
            () -> {
                try {
                    while(true) {
                        Runnable event = queue.take();
                        event.run();
                    }
                } catch (InterruptedExcution e){}
            }
        );
        loop.start();

        queue.put(() -> System.out.println("event occurs"));

Q3. restFull -> patch, put 차이점
A3. 기본적으로 restFull이란, Front와 Back을 분리하는 설계, 원칙으로서
백엔드 단에서는 api요청 등에 따라 DB와 통신하며 데이터를 CRUD하며 이를 버퍼나 스레드, 기타 컬렉션 라이브러리 함수에
탑재시키는 역할을 한다. 반면 Front는 백엔드api와 통신한 값들을 기반으로 일반 고객들이 접하는 화면을 렌더링하게 만든다.

여기서 프론트(예를들어 리액트나)서버가 백엔드서버에 요청(대부분 json값으로)을 보내는데, 그 요청중 한 종류로서
patch : 데이터 전체가 아닌 달라진 값들 일부만 새로 갱신하는 요청, 요청에서 빠진 필드는 삭제되거나 기본값으로 초기화, 멱등
put : 데이터 전체를 새로 갱신하는 요청
으로 정리할 수 있음, 전송량이 적어서 가볍고, 구현 방식에 따라 비멱등
